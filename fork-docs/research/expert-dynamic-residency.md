動的 Expert 常駐の比較メモ

LLAMA_EXPERT_DYNAMIC_RESIDENT=1 をモデル読み込み時に設定すると、同期 Vulkan の packed Expert 配置で動的常駐が有効になります。未設定または 0 は固定配置です。LLAMA_EXPERT_SCRATCH_REUSE=1 と LLAMA_EXPERT_BATCH_UPLOAD=1 を両条件で揃え、LLAMA_EXPERT_OVERLAP を解除してください。モデル、プロンプト、seed、生成長、ubatch=1、MTP 無効を揃えて比較します。

各層の VRAM 枠 300 常駐 + 10 scratch と RAM の 212 枠は固定です。Scratch ヒットがあり、その層で直近 32 回以上使われていない未選択の常駐 Expert があれば、最も古い候補と入れ替えます。1 層の照会当たり最大 1 回です。退避側の全重みを一時 RAM に同期で読み戻し、昇格側が明け渡す RAM 枠に保存します。その後、2 つの既存 GPU 枠の役割を切り替えます。GPU 内で重みをコピーする必要はありません。一時バッファは最も大きい層の Expert 1 件分で、比較対象では 2,662,400 バイトです。Gate/up が融合した 2 テンソル構成と、個別になった 3 テンソル構成に対応します。層をまたぐ容量の再配分やバックグラウンドでの書き戻しは、この実装の範囲外です。

常駐と RAM の対応表はモデルが保持します。同じモデルでコンテキストを開き直すと、常駐枠を検証してから物理的な空き枠を scratch として再構成し、scratch の中身の記録と選択履歴を初期化します。書き戻しの読み出しが途中で失敗した場合、RAM の正本と所有権は読み出し前の状態に残ります。

出力が一致すること、生成 tok/s、permanent_hits、scratch_hits、ram_uploads を比較します。動的常駐の終了ログには昇格・退避件数、書き戻しバイト数と時間、アップロードバイト数、合計転送バイト数と時間が出ます。合計時間はアップロード計画、ホスト側コピー、待機を含む区間の合計で、DMA 単体の時間ではありません。

MSVC 構文確認と CPU の所有権テスト 4 件が成功しました。テストは未選択・経過回数の条件、融合版と分離版の昇格時の重みと枠の整合、読み出し途中の例外での保全、コンテキスト再作成時の scratch 枠再構成と重複枠の拒否です。モデル実行、出力一致、実測性能は未確認です。
