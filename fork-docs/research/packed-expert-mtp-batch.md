# Packed Expert two-token MTP verification

Opt in at model load with LLAMA_EXPERT_BATCH_TOKENS=2, LLAMA_EXPERT_DYNAMIC_RESIDENT=1. Only synchronous Vulkan placement and a single sequence are supported. Unset/default preserves the single-token path. The capacity guard checks counts before multiplication.

The 48 layers retain 300 permanent slots and reserve 20 scratch slots each. The shared Expert map indexes the union of selected Experts across up to two tokens; all selected slots are protected through computation. Duplicate cold requests generate one upload per Expert but request misses are counted per occurrence. Use `packed expert requests` for hit rate and `ram_uploads` for physical upload count. Dynamic promotion remains at most once per layer lookup; the 32-lookup staleness horizon is measured in batches, so batching changes its token horizon.

Exact additional GPU weight payload versus scratch10: 982272000 bytes (936.77 MiB). Native host upload staging grows to 53248032 bytes. One additional target recurrent state row is approximately112.57 MiB on CUDA. Based on the prior free Vulkan1908 MiB there is about971 MiB left before new compute overhead; actual runtime allocation still requires validation. Three-token capacity is intentionally not supported.

With target -ub2 and --spec-draft-n-max1, existing recurrent snapshots provide n_rs_seq1 and allow rejection rollback without FULL checkpoint/replay. -ub1 with the same model capacity falls back to n_rs_seq0 and the prior checkpoint path. No new scheduler or speculative engine is added. The batch allocator now allows a tail exactly as large as its microbatch and fixes the disjoint-sequence capacity guard (>= rather than >).
