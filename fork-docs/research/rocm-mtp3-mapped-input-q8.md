# MI50への共有RAM入力コピーとQ8_1量子化の統合

統合版 `24eba4dbc` を起点とする。対象はgfx906の単一バンク・固定3幅で、RTXが共有のピン留めRAMへ書いた活性値をMI50のRouted Expertが受け取る経路。従来は30,720 BのF32を専用カーネルでMI50へコピーし、gate/upの前にQ8_1へ変換する。保存トレースでは各48回/検証、GPU時間は0.380と0.214 ms/検証だった。PCIe読み取りと量子化は引き続き必要になる。[統合版のトレース](../rocm/latest-performance.md#d4採用後の統合版で検証を詳細計測)

## 変更範囲と確認条件

- 共有RAMのF32を既存のQ8_1変換へ直接渡し、MI50の中間F32コピーを省く。既存の共有RAMスロットの寿命と、HIP Graph再利用中の入力アドレスを確認する。CPU Expertは共有RAMのF32を使う。通常の入力コピーとQ8_1変換をフォールバックに使う。
- フラグは既定OFFとし、リクエスト間で切り替える。採用済みのLRU、Strata、CPU Expert、先読み、昇格を使う。
- MI50で同一F32入力から、従来のコピー経由と共有RAMから直接読み出したQ8_1の全バイトを照合する。量子化の整数値、スケール、ブロック和を含む。
- 診断用処理とプロファイラーを外し、固定5問の会話履歴・MTP候補・生成IDを共通化する。固定3幅・4K・上限512の本体検証時間をON/OFFで比較する。適用回数、通常H2D、EOS、スワップも記録する。

## 対象の経路と切り替え

`LLAMA_EXPERT_OUTPUT_MODE_FILE` に `MAPPED_INPUT_Q8=on` または `MAPPED_INPUT_Q8=off` を書く。未指定はOFF。比較では同じファイルで `SCRATCH_LRU=on` を維持し、待機中にファイルを置き換える。変更は次の要求で反映される。

ONでは元の入力コピーの時点で、既存のQ8_1カーネルがピン留めした共有RAMを直接読み、元のMI50入力バッファに8,640 BのQ8_1を書き込む。実際の利用先が固定3幅のIQ2_SまたはIQ3_XXSのgate/upだけであるとスケジューラで確認する。通常のMMVQとStrataはそのQ8_1を再利用する。CPU Expertは元の共有RAMのF32を読む。HIP Graphは従来のF32入力と、前もって量子化した入力を区別する。条件を満たさない層は従来のF32コピーと量子化を使う。

## MI50の実入力でのビット一致

実装 `9bc860c2c` をCUDA/ROCm開発イメージで増分ビルドした。短い実モデル応答では `GGML_HIP_MAPPED_INPUT_Q8_CHECK=1` を起動時に加え、LRUと試作をONにした。同一の共有RAM入力を、従来のF32コピー後に量子化する経路と、共有RAMからそのまま量子化する経路へ通した。3サンプルの各8,640 B（240ブロック、整数値・スケール・和を含む）がすべてビット一致。固定3幅3検証の144層で、試作の適用141、従来経路への復帰3。サーバー終了コード0。同期を伴う照合は速度比較で無効にする。最初のランナーは接続先ポートを誤り、次の試行はビット一致したもののモードファイルと終了管理の設定に不備があった。設定を修正した最後の診断だけを正式結果とした。[診断ログ](/home/t-saka/rocm-mapped-input-q8-20261128/live-test/diagnostic-final)

## 固定5問の本体検証時間

診断と同じビルドで、量子化の照合とGPUプロファイラーを無効にした。LRUをONとし、固定3幅・4K・上限512で、同一サーバーのOFF→ON→ON→OFFを比較した。各回の前に同じ8トークンのウォームアップとスロット消去を行い、第1問の入力キャッシュは0。記録済みの5問を読み取り専用で再生し、全回の入力、候補・採用イベント、生成IDと本文の一致を確認した。各回527検証・MTP採用686 / 1,054・生成1,215トークン、全20応答EOS。Expert常駐状態と実際のRouter選択は固定していない。
