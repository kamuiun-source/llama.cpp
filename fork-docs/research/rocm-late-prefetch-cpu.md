# 固定3幅で未完了の先読みExpertをCPUへ振り替える試作

対象は単一バンクのHIP tuple DMA。通常のCPU補正が有効で、既存の物理コア予算に空きがある層だけを対象にする。実ミス1件をCPUで処理する場合は最大4ワーカーを割り当てるため、追加で振り替えない。通常の実ミスの選択と優先順位は維持する。CPUの追加投入が失敗した場合は通常の実ミスだけで再試行する。

発行済みの先読みのうち実際に選ばれ、常駐枠・仮置き枠にないExpertを対象にする。最後に発行した該当Expertが1位置で使われ、先行する該当Expertが完了済みで、最後のイベントが照会時に未完了だった場合に、最大1件をCPUに渡す。照会は最大2件。イベント待ちの対象は先行分までに縮まり、先行分がない場合はGPU側の先読み待ちの発行を省く。CPUで使う原本は昇格で書き戻すRAM枠と重ならないことを確認する。発行済みH2Dは継続し、先読みバンク再利用や昇格の安全確認、末尾の完了待ちは従来どおり。

起動時に `LLAMA_EXPERT_HIP_MTP3_LATE_PREFETCH_CPU_MODE_FILE` にモードファイルのパスを指定する。内容は `LATE_PREFETCH_CPU=off` または `LATE_PREFETCH_CPU=on`。既定OFF。同じサーバーの全スロットが空いた後、次の生成リクエストで切り替える。通常のCPU Expert補正と先読みのper-slotイベントを有効にして比較する。

終了時の `packed HIP MTP3 late prefetch CPU` は振替件数、GPU側の先読みイベント待ちを発行しなかった回数、D2Dを省いた件数・バイト数を出す。発行済みH2Dのキャンセルや待ち時間の削減量は含まない。CPU補正で加算のまとまりが変わり得る。固定5問では生成IDとMTP受理件数に加え、第4問のPythonコードと数値、CPU合流待ち、末尾の先読み待ち、本体検証時間を比較する。
