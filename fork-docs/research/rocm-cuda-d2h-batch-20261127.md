# 固定3幅のRTX→MI50でRouter読み戻しを一括発行

対象はRTX 4070 Ti＋MI50、CUDA 12.9、固定3幅の採用設定。RTXが活性値30,720 Bを共有RAMへ直接書く層でも、現層のRouter ID（I32×30）とRouter重み（F32×30）はRTX VRAMにあり、共有ピン留めRAMへのD2Hが2件残る。既存のスケジューラが活性値を除外した後の読み戻しで、独立した2件・計240 Bを1回の `cuMemcpyBatchAsync` へ渡す。活性値が既存の理由でマップされない層でも、2～3件の独立したピン留めD2Hは対象になる。[既存の共有RAM経路](../rocm/10-decode-pipeline.md#mi50のカーネルで共有ramから活性値を読む試作)

CUDAの同じデバイスとスレッド別既定ストリームを使う。既存のRTX生産完了待ち、MI50のピン留め領域再利用待ち、D2H完了待ちを維持する。共有RAMへの活性値の直接書き込み、MI50のマップ済み読み出しとHIP側の転送は既存経路を使う。CUDA 12.9ヘッダーの12080 ABIを動的に解決する。APIが利用できない、対象が1件、ピン留めされていない、または領域が重なる場合は従来の読み戻しを使う。一括発行後のエラーは、部分発行の可能性があるため失敗として停止する。[CUDA Driver API](https://docs.nvidia.com/cuda/archive/12.9.0/cuda-driver-api/group__CUDA__MEM.html)

既定OFF。サーバー起動環境の `LLAMA_EXPERT_HIP_MTP3_COPY_API_BATCH_MODE_FILE` にモードファイルのパスを渡し、内容を `COPY_API_BATCH=off` または `COPY_API_BATCH=on` とする。同じサーバーで全スロットが空いているリクエスト境界に反映する。終了ログの `packed HIP MTP3 CUDA D2H batch` に2件・3件別の適格／適用数、バイト数、マップ経路の適格／適用数、理由別フォールバック数を出す。カウンターはONだったリクエストの累計。

CUDA 12.9コンテナで一括発行関数を単独コンパイルし、スケジューラ本体とサーバーのモードヘッダーを構文確認した。ホストの小規模テストで独立2件の適用と、重複領域・1件の除外を確認した。GPU・モデル実行は未実施。固定3幅の通常設定でまず `mapped_applied` と `applied_2` の発動、既存の活性値読み出し件数、生成IDとMTP採用数を照合する。2件を1回のAPIに渡す効果をCUDA側のホスト発行時間で評価し、DMA件数や全体速度は実測で判断する。
