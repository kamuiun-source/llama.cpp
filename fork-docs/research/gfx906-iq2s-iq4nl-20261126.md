# gfx906のIQ2_SとIQ4_NLの再調査

2026-11-26。統合ブランチ `50810b506` の固定MTP 3幅、単一バンク、Expert直接DMA、CPU Expert自動配分が対象。採用設定の同時トレースではIQ2_S gate/up＋SwiGLUが4.415 ms/検証、IQ4_NL downが3.763 ms/検証。通常実行の壁時計や他カーネルと単純には合算しない。[計測サマリ](../rocm/latest-performance.md)

## IQ2_S gate/up＋SwiGLU

現行は符号復号ON、LDSなし・2出力行で、gateとupのQ8_1入力をレジスタで共有する。採用試験ではカーネルの合計4.877→4.344 ms/検証、5問の生成ID・MTP採用数は一致した。LDS先読みと4行は通常OFF。入力共有と符号復号に加えて、前回のLDS全体の先読みを繰り返す根拠は薄い。[既存実装と計測](../rocm/10-decode-pipeline.md#iq2_sのgateupでq8_1入力を共有)

FLUTEの§3.1–3.2は、圧縮重みの取り出しに合わせたデータ配置と、複数値をまとめて取得するLUTを扱う。対象のCUDA Tensor Core経路の速度はgfx906には転用できない。ここではLUTのまとめ方だけを参考にする。Alex Reinkingの論文の付録Bは、IQ2_Sの10ビット格子IDと独立した符号ビットを整理している。評価はCPUとMetalを含み、今回のgfx906のExpert経路の性能は示していない。[FLUTE](https://arxiv.org/abs/2407.10960) · [User-Schedulable Approximations for Quantized Tensor Programs](https://arxiv.org/abs/2611.17526) · [IQ2_S導入PR](https://github.com/ggml-org/llama.cpp/pull/5721)

現行の `iq2s_grid` 1,024要素を数えると、絶対値は8・25・43の3種で、下位・上位4値を共通のパターン表にすると81種類。各パターン×16符号をint8×4の1語で置くと5,184 B、格子ID→上下のパターンIDを2 B/要素で置くと2,048 B、合計7,232 B。全1,024格子×256符号で、生成した符号付きバイト列が現行の復号と同じことをホスト上で照合した。

候補は、採用済みのgate/up共有とDP4Aの順序を保ち、逐次符号処理を符号込みの4値LUTに置き換える試作。重み・DMA形式を維持できる。追加の依存ロードとLDSに置く場合のバンク競合が主なリスク。2行・同じ重み、入力、Expert IDで、全出力の一致、カーネル時間、VALU・メモリ命令、VGPRとLDS使用量を比較する。追加GPU計測は未実施。

## IQ4_NL down

現行のK=640・M=2,560・3位置・top-10の2行経路は、Q8_1の量子値とスケールを両出力行で共有し、採用済みの `v_and_or_b32` で復号セレクタを短縮している。過去の合成試験で外部読み出し要求を96.2%減らしても、カウンター付き中央値は75.20→72.00 µs。依然残る時間にはキャッシュからのロード、復号、整数内積、リダクションが含まれる。3行詰めは単体で改善したが、加算順が変わり、実モデルの速度とMTPも変動した。[従来の内訳と試作](../rocm/10-decode-pipeline.md#固定3幅のiq4_nl-downの内訳)

1. **IQ4_NLのニブル列・FP16スケールの分離。** Furnaceのgfx906実装は、IQ4_NLのニブルとスケールのビットを維持して別の面に配置する。公開コードの適格条件は2次元重み。固定3幅のExpert downへの移植では、まずMI50に配置済みの1層で復号・ロードだけを測る。整数の積和順とFP32の加算順を維持する。実モデルへ広げる場合は、常駐・仮置き・直接DMAの各スロットで同じ配置を使う必要がある。[Furnaceの適格条件](https://github.com/sixvolts/llamacpp-gfx906-furnace/blob/d2b951322ec1a1f168d1f1006bc380704ee63c1b/ggml/src/ggml-cuda/repack-gcn.cu#L137-L144) · [FurnaceのIQ4_NL変換](https://github.com/sixvolts/llamacpp-gfx906-furnace/blob/d2b951322ec1a1f168d1f1006bc380704ee63c1b/ggml/src/ggml-cuda/repack-gcn.cu#L452-L465)
2. **32値ブロックを1レーンで担当する割り当て。** HerReiのgfx906実装はExpert IDを受け取れるが、公開パッチの適用は入力1位置。Radeon VIIでIQ4_NLは広い形状の中央値約15%短縮を報告。3位置・K=640での速度は不明。既存の3行詰めとは割り当てが異なり、出力行当たりのレーン数と加算順の扱いを確認してから比較する。[HerReiの計測と適用条件](https://github.com/HerRei/gfx906-decode-kernels) · [カーネル差分](https://github.com/HerRei/gfx906-decode-kernels/blob/main/matvec/gcn-mmv.diff)
3. **downとExpert加重加算の融合。** MonoMoEはUp・活性化・Down・加重加算の間の中間データを除く設計を先端NVIDIA GPUで実測した。Furnaceにもdown＋reduceの例があるが、実装はQ5_1・1位置で、部分和へ重みを掛けるため加算順が変わる。こちらの過去トレースでは加重加算単体は約0.24 ms/検証で、融合で加わる同期・リダクションを引いて評価する。既存のCPU Expert補正、Q8_1量子化とGPU間返却の境界は維持する。[MonoMoE](https://arxiv.org/abs/2609.04244) · [Furnaceのdown融合](https://github.com/sixvolts/llamacpp-gfx906-furnace/blob/d2b951322ec1a1f168d1f1006bc380704ee63c1b/ggml/src/ggml-cuda/repack-gcn.cu#L5916-L5935)

優先順はIQ2_Sの符号込みLUT、IQ4_NLの1層だけの再配置。どちらも既存の固定3幅カーネル時間と出力を単体で比較できる。GPUで改善が再現した案を実モデルに持ち込む。

## IQ2_Sの符号込みLUT試作

`codex/rocm-iq2s-signed-lut` で固定3位置・2行のgfx906 IQ2_S gate/up＋SwiGLUに限定。既存の符号復号・Q8_1入力共有・加算順・直接DMAの配置を維持し、7,232 Bの読み取り専用デバイス表から符号付き4値を得る。活性値やLUTをLDSに置く処理は追加していない。

サーバーでは `LLAMA_HIP_GFX906_IQ2_S_LUT_MODE_FILE` の `IQ2_S_LUT=on` と `IQ2_S_LUT=off` をリクエスト間に読む。既定OFF。切り替えで対象のHIP Graphの再利用条件が変わる。採用済みの `GGML_HIP_GFX906_IQ_SIGN_DECODE=1` と `GGML_HIP_GFX906_IQ2_S_PAIRED_DOT=1` が対象経路の前提。IQ2_SのLDS先読みと出力4行はOFFで比較する。

Lunaが同じgfx906 HIPライブラリ、同じプロセスとグラフでOFF→ON→ON→OFFを比較。K=2,560、M=640、3位置・2出力行・top-10、16 Expert、Expert連続配置を模した固定シードの合成重み・入力・Expert ID。ウォームアップ各50回、測定各1,000回。出力19,200要素は全4試行でビット一致。プロファイラーなしのグラフ実行の平均はOFF 167.324 / 169.784 µs、ON 251.695 / 251.810 µs。試作ONは約49%遅い。[実行ログ](/home/t-saka/rocm-iq2s-signed-lut-20261126/logs/run-unprofiled-retry.log)

rocprofv3の別計測で確定したカーネル単体の平均はOFF **151.813 µs**、ON **238.464 µs**（各200起動、ウォームアップ各50を除外、57.1%増）。OFF→ON→ON→OFFの各平均は145.693 / 237.025 / 239.902 / 157.934 µsで、OFFへ戻した際に従来カーネルが再び起動した。workgroupは両条件64×3、グリッドは20,480×30。プロファイルあり・なし両方のFP32出力ファイルのSHA-256が一致し、HIPコンパイル、リンク、単体ベンチ、rocprofv3は終了コード0。確認範囲はHIPバックエンドの切り替えと単体経路。サーバーのリクエスト受付経由での切り替えと実モデルは未計測。試作は既定OFFのまま保留。[カーネル計時と資源の生ログ](/home/t-saka/rocm-iq2s-signed-lut-20261126/profile/lut-kernel-trace_kernel_trace.csv)

gfx906コードオブジェクトではVGPRが56→64、SGPRは44のまま、LDSは固定・動的とも0 B、scratchとVGPRスピルは両方0。逆アセンブル全体の静的命令数は `global_load*` が42→74、`s_waitcnt` が56→80、`v_dot4_i32_i8` は32で同じ。ベクトル命令は607→567。符号を算術で作る命令は減ったが、パターンIDを読んでから符号付き値を引く依存ロードが増えた。観測した失速と整合するが、それぞれの寄与を分離した値ではない。[コードオブジェクトと逆アセンブル](/home/t-saka/rocm-iq2s-signed-lut-20261126/obj-review)
