### Linux ROCm の転送改善

- デコード全体の改善は `ac5bb7770` から同じ `codex/rocm-single-bank-mtp3` で進めた。[4項目の計測メモ](../rocm/10-decode-pipeline.md) を参照。Shared Expert先行発行のキャッシュ再実行は41.66→42.64 tok/s、RTXとMI50の計算重複は別トレースで64.64 ms。両ランタイムで登録したホスト領域は別の比較で41.63→42.70 tok/s。幅3のSSM履歴融合は41.66→41.90 tok/s、固定3位置のdevice pendingはD2H 153→1回・H2D 121→2回で41.66→41.34 tok/s。全条件で生成IDが一致。4項目を既定OFFの試作として保持した。以降は新しいONだけを測定して既存OFFと比較する。
- 同じ8K入力で② ONのキャッシュ再実行50検証を計測。通常の本体検証52.14 ms/回、生成42.32 tok/s。転送元待ち31.64 msの大半は先行GPU処理で、同条件のトレースでは96.5%が計算・コピーと重複。通常の読み書き6.24 msのうち5.29 msがMI50側。ExpertのステージングCPUコピーは2.27 ms。受け渡しの次の調査対象はMI50側の小容量H2D/D2H。 [方向別の計測メモ](../rocm/10-decode-pipeline.md#ピン留め版のキャッシュ再実行での受け渡し内訳)
- 同ブランチで入力H2D・戻りD2H・スロット表・昇格の書き戻しを非同期化する4試作を追加。ユーザーの指定で全ONを同じ8K入力の1起動で比較し、キャッシュ再実行42.32→44.77 tok/s、本体検証52.14→48.67 ms。生成IDとMTP採用100件中76件は一致し、中断後の16トークンも一致。Expertコールバックは10.46→7.25 ms/検証。戻りD2Hは全測定5,280件中4,950件で発動し、昇格1,709件は確定済み。施策別の寄与は未確定。 [全ONの計測メモ](../rocm/10-decode-pipeline.md#4項目を有効にした実機比較)

- 固定3幅の作業は `codex/rocm-single-bank-mtp3`。同じ8K入力の単一バンク計測では、履歴由来のExpert先読み候補はキャッシュ再実行で必要量に対して転送量が多く、空き枠限定では0件。`LLAMA_EXPERT_HIP_MTP3_DIRECT_RAM=1` は原本19.39 GiBを全量ピン留めし、3位置検証のステージングコピーを省いた。全8応答で出力は一致。OFF / ONの生成速度は8K初回33.51 / 33.23、キャッシュ再実行41.46 / 37.11 tok/s。ONの再実行で転送完了待ちに大きなばらつきがあり、既定はOFF。検証条件と根拠は [固定3幅の計測メモ](../rocm/09-single-bank-mtp3.md) に記録した。
- 直接DMAは `c6cfb7567` にコミット。同じブランチのgate/upのみの分割試作 `LLAMA_EXPERT_HIP_MTP3_GATE_UP_OVERLAP=1` は、ミス0でミス側の投影・合流を省き、全レーンのSwiGLU・downを各1回実行する。同じ8K入力のOFF / ONは初回32.57 / 31.82、キャッシュ再実行41.53 / 39.59 tok/s。全8応答の出力は一致し、再実行の転送完了待ちは160.66 / 14.55 ms。融合解除や追加の処理を含む全体の速度では改善がなく、既定はOFF。 [固定3幅の計測メモ](../rocm/09-single-bank-mtp3.md)
- gate/up分割版は `963d4218e` にコミットし、フォークの `codex/rocm-single-bank-mtp3` にpush済み。追加の `LLAMA_EXPERT_HIP_MTP3_GATE_UP_FUSE_HITS=1` で全ヒット2,089層を融合に戻した。新しい3条件の比較は、並行化OFF / 分割 / 融合の順で初回31.80 / 31.39 / 31.98、キャッシュ再実行41.12 / 38.14 / 38.33 tok/s。全12応答の出力は一致。融合版でもグラフ分割は検証50回で9,700回、並行化OFFでは4,900回だった。単一バンクの既定は並行化OFF。 [固定3幅の計測メモ](../rocm/09-single-bank-mtp3.md)
