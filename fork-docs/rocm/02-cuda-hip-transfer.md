# 02 CUDA と HIP の共存・GPU 間転送

状態: 02-1〜02-3 完了。CUDA と HIP の同一プロセス内の演算、CPU RAM 経由の同期コピー、転送時間の基準を確認済み。

## 現状

CUDA と HIP のプラグインは同じバックエンド GUID を使う。ランタイムを区別する必要のある箇所は、登録元やバッファの所有元を照合する。既存の異種バッファ間コピーは同期ホスト経由から検証できる。

## 先行調査

- 02-1 は Phase 01 の2位置ケースを流用する。バックエンド指定を省略すると、1回の `test-backend-ops` で CUDA0 と ROCm0 が順番に同じ2ケースを CPU 参照と比較する。
- `ggml_backend_tensor_copy` は宛先の直接コピーを試し、対応していなければ CPU メモリへの読み出しと宛先への書き込みにフォールバックする。CUDA/HIP は同じ GUID を返すが、直接コピー側にはプラグイン固有のバッファ関数の照合もある。まず既存の同期経路の動作を確認する。 [コピーとフォールバック](../../ggml/src/ggml-backend.cpp#L869) · [バッファ所有元の判定](../../ggml/src/ggml-cuda/ggml-cuda.cu#L988)
- `ggml_backend_event_wait` は渡されたイベントを宛先の実装へ渡す。02-2 は各 GPU の完了をホストで待ち、所有元が異なるイベントを渡さずに検証する。テストは同時に確保した2 GPU のバッファで、異なる固定パターンを両方向にコピーして照合する。 [イベント待ち](../../ggml/src/ggml-backend.cpp#L1006)
- 02-3 の初回は、同期コピーの基準時間のみを、Flash-Next の3位置分の活性に相当する 30 KiB を目安に測る。チェック用のバイト照合は計時外とし、再利用バッファやピン留めの導入は基準値を確認してから判断する。

2026-11-20、02-1 は開発用 Docker で CUDA0（RTX 4070 Ti、sm_89）と ROCm0（MI50、gfx906）を同じ `test-backend-ops` プロセスに読み込んだ。両 GPU とも2位置の IQ3_XXS gate/up と IQ4_NL down が CPU 参照と一致し、各 2/2 ケース合格。生ログは Git 外の `/tmp/llama-rocm-02-1-dual-device-test.log`。

02-2 は `test-backend-tensor --cuda-hip-copy` を追加し、両 GPU のバッファを同時に確保して、各バックエンドを同期した後に 30,720 バイトをコピーした。送信パターンは方向ごとに変え、宛先はコピー前に別の値で埋めた。CUDA0 → ROCm0 と逆方向の両方がバイト単位で一致し、終了コードは 0。生ログは Git 外の `/tmp/llama-rocm-02-2-cuda-hip-copy.log`。

02-3 は `test-backend-tensor --cuda-hip-copy --timing` で各方向1,000回のコピーを2回測定した。同期と既存コピー経路のホストバッファ確保・転送を計時に含め、最初の入力書き込みと照合用の読み戻しは計時外。測定後の結果は全方向で一致した。

| 30 KiB の同期コピー | 1回目（µs/copy） | 2回目（µs/copy） |
| --- | ---: | ---: |
| CUDA0 → ROCm0 | 22.616 | 21.568 |
| ROCm0 → CUDA0 | 22.789 | 21.975 |

単独の同期コピーの基準値。推論中の転送待ちと重複度はモデル実行で確認する。転送バッファの再利用やピン留めは、この実行経路が律速と確認できた時点で検討する。生ログは Git 外の `/tmp/llama-rocm-02-3-copy-timing-run{1,2}.log`。

## 小分けの作業

| 作業 | 変更範囲 | 確認してから次に進む条件 |
| --- | --- | --- |
| 02-1 同一プロセスで各 GPU を検証 | 既存バックエンドで CUDA0 と ROCm0 に小さなグラフを個別に実行する。 | 両方が CPU 参照に一致し、実行と解放が成功する。 |
| 02-2 同期コピーを往復させる | 固定データを CUDA → RAM → HIP と逆方向へ転送する。失敗が再現した箇所だけ所有元判定を修正する。 | バイト単位で一致し、別ランタイムのイベントや VRAM ポインタを渡していない。 |
| 02-3 転送コストを測る | 同期コピーの転送時間を記録する。効果が見込める場合に限り、ホストバッファの再利用とピン留めを個別に試す。 | 正確性を維持し、各変更の費用と効果を個別に説明できる。 |

## 完了条件

両方向のコピーが参照データとバイト単位で一致し、転送と解放を繰り返しても破損しない。CUDA と HIP の間でランタイム固有のイベントや VRAM ポインタを渡さない。根拠は [Vulkan Expert 実装の ROCm 移植調査](../research/linux-rocm-portability.md) を参照。
