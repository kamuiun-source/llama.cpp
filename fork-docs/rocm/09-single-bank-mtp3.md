# ROCm 単一バンクの固定3幅 MTP

統合ブランチ `d9287e566` から `codex/rocm-single-bank-mtp3` に分ける。RTX 4070 Ti と MI50 で、Flash Next UD-IQ3_XXS と Q8_0 の MTP ドラフトを使う。

| 作業 | 変更範囲 | 確認条件 |
| --- | --- | --- |
| 単一バンクの検証幅を拡張する | 単一バンクの動的配置で固定3位置を許可し、最大30 Expert 選択を既存の仮置き枠とアップロード処理で扱う。 | 3位置が1回の本体検証に入り、2幅と既存の分割バンクの設定が使える。 |
| 候補棄却時の巻き戻しを確認する | 本体の再帰状態スナップショットとドラフトの部分削除を使う。 | 両候補棄却、第1候補のみ採用、両候補採用で、それぞれ本体とドラフトの末尾が2、1、0位置戻り、次の検証に進む。 |
| 同じ8K入力で2幅と3幅を比較する | 配置プロファイル、コンテキスト、入力、生成上限をそろえる。同じバイナリで固定幅を切り替える。 | 生成速度、第1・第2候補の採用率、GPU同期待ちを含む本体検証1回の時間を記録する。巻き戻しの詳細ログは別の実行で採る。 |

単一バンクの `LLAMA_EXPERT_HIP_DYNAMIC_RESIDENCY=1` 設定に、固定3幅では `LLAMA_MTP_VERIFY_THREE=1` と `--spec-draft-n-max 2` を加える。通常の `-ub 2` は維持する。仮置きは20枠から30枠へ広がり、広幅Prefillの転送に使うのは従来と同じ10枠ずつの2組。候補1個の固定2幅では `--spec-draft-n-max 1` を使う。

固定3幅の通常起動では、入力H2D、戻りD2H、スロット表、昇格時の書き戻しを非同期化し、Expertの連続配置・直接DMAも有効にする。[Dockerの採用設定](10-decode-pipeline.md#単一バンク固定3幅の採用設定) を参照。

固定3幅の検証グラフは、3トークンの通常Prefillとは区別して再利用する。HIP の生成検証では packed decode で Router ID とスロット表を処理する。初期試作では幅だけを判定したため生成検証が compact prefill に入り、その速度は採用比較から除いた。

### 現在の隠れ状態で次層のRouterを先に実行する候補

層LのRouterに入力する隠れ状態を、同じトークンの層L+1のRouter重みに適用し、予測したExpertのうちMI50にないものを層Lの計算中に先読みする。層L+1に到達したら、その時点の入力で通常のRouterを実行し、必要なExpertが揃うまで不足分を転送する。上の履歴ベースの集計ではこの予測を行っていない。本フォークでこの方式の予測精度、転送の重なり、速度は未計測。

Mixtral-Offloadingの§3.2–3.3は隣接層の残差接続を根拠に、現在層のRouter入力と次層の既存Routerを使う。現在層の必須ロード後に次層の候補1〜2件を別枠へ先読みし、実際に参照する場合にキャッシュへ取り込む。AdapMoEも既存の後続層のゲートを利用する。Qwen3-30B-A3Bの別研究では最初の2層で状態差が目立ち、それ以降の予測recall@kは平均約90%だった。これはQwen3.8 Flash Nextのキャッシュミス捕捉率や速度の実測ではない。[Mixtral-Offloading](https://arxiv.org/html/2312.17238) · [AdapMoE](https://arxiv.org/html/2408.10284) · [Speculating Experts Accelerates Inference](https://arxiv.org/html/2603.19289)

フォークのQWEN4EXPは、AttentionまたはRecurrentの後にHCのFFN入力 `ffn_mix.cur` を作り、層別の `ffn_gate_inp` に渡す。予測に使える入力はこの層L側のテンソル。層L+1の正規の入力はその層のAttentionまたはRecurrentとHC処理を経るため、層ごとの精度は実測する。固定3幅の照合では、3位置の候補を層内で重複排除し、対象層での実ミスの捕捉件数・バイト数と不要転送量を集計する。実転送を評価する場合は、層L+1のRouter確定までに完了した分と、転送・予測に起因する待ちを区別する。過去のID・スロットトレースにはRouter入力がないため、比較には予測側のIDの追加記録が必要。

## RAM原本からMI50へ直接アップロードする試作

| 作業 | 変更範囲 | 確認条件 |

`LLAMA_EXPERT_HIP_MTP3_DIRECT_RAM=1` で有効化する。既存のHIPホストバッファ型で全RAM原本を確保し、テンソルごとに実際のバッファ型を確認する。ページ可能メモリに置かれた原本があれば、バイト数を記録して起動を止める。3位置検証のミス時に従来と同じMI50ストリームへ原本の各プレーンから非同期H2Dを発行し、既存の同期を通ってから昇格・書き戻しとスロット更新に進む。通常の1・2位置デコードとPrefillでは既存のステージング経路を使う。
