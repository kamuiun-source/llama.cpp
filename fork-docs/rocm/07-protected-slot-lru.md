# HIP 分割バンクの仮置き枠の LRU

## Phase 1

- 基準は `d9287e566` の Phase 0 昇格OFF。各層の保護300・仮置き20、HIP 分割バンク、MTP 2位置を使用する。
- `LLAMA_EXPERT_HIP_SLOT_POLICY=protected` で、空いている仮置き枠を先に使い、満杯のときは現在の2位置が選んでいない Expert のうち最終利用が最も古い枠を再利用する。常駐側とRAMの所有表は固定し、既存の packed アップロードと転送完了待ちを使う。
- 同じ実行ファイルで設定を切り替え、Flash Next UD-IQ3_XXS、Q8_0 ドラフト1候補、同じ top300、固定プロンプト1、生成上限128を揃える。昇格OFFとLRUを両順で計測し、生成速度、入力処理を含む要求ミス、書き戻し量、生成IDとMTP採用数を確認する。

### 実機結果

| 構成 | Generation（各2回） | Generation（合算） | 要求ミス | RAMからのアップロード |
| --- | ---: | ---: | ---: | ---: |
| 従来の昇格OFF | 26.85 / 27.21 t/s | 27.03 t/s | 12,336 / 100,320（12.30%） | 10,884件、21,364.21 MiB |
| 保護＋仮置きLRU | 26.84 / 27.57 t/s | 27.20 t/s | 10,265 / 100,320（10.23%） | 9,140件、17,928.25 MiB |

昇格OFF → LRU → LRU → 昇格OFFの4回で、128トークンの生成IDとMTP提案73・採用54が一致した。両条件とも書き戻しは0。LRUで要求ミスは2.06ポイント、アップロード量は約16.1%減った。生成速度差は約0.6%で、今回の試行のばらつきに収まる。ミスと転送量は入力処理を含む。速度の合算は初回トークン後の127トークン/試行で算出した。生ログは Git 外の `/tmp/llama-rocm-phase-1-protected-lru/`。

## Phase 2 リクエスト間の対交換

- 保護300・仮置き20と既存のLRUを使う。サーバーのリクエスト境界で、固定規則で選んだRAM側のExpertと保護側のExpertを対で交換する。生成中のスロットコールバックから交換を呼ばない。
- 昇格対象を仮置き枠で確保してから、退避対象の各プレーンをページ固定の作業領域に読み戻す。必要な転送を終えてから、昇格対象が使っていたRAM枠を退避対象に渡し、所有表を更新する。
- 読み込み途中と書き戻し途中の中断を、投入済みのコピーを回収する形で再現する。所有表と原本を確認し、完了後に同じプロンプトで生成を再開する。同じモデルとプロンプトで、各条件とも先行リクエストから交換後のリクエストまでを計測する。

`llama-server` の通常のテキスト生成1スロットで、Phase 1の設定に `LLAMA_EXPERT_HIP_SLOT_EXCHANGE=1` を加える。各層で最初の有効な仮置き Expert と、IDが最小の保護 Expert を最大1組選ぶ。GPUの追加枠は使わない。回復診断でのみ `LLAMA_EXPERT_HIP_SLOT_EXCHANGE_FAULT=h2d` または `d2h` を指定する。最初の対象コピーで一度だけ中断し、投入済みのコピーを待った後に、RAM・GPUの保護枠・仮置き枠のバイト列と所有表を検証する。

### 実機結果

Phase 1 → Phase 2 → Phase 2 → Phase 1 の順で、サーバー起動ごとに同じプロンプトをキャッシュ無効で2回送信した。すべて入力63・生成128トークンで、8回答の生成IDは一致した。MTPは各初回で提案73・採用54、各2回目で提案72・採用55だった。

| 構成 | 2回目のGeneration（各2回） | 2回目のGeneration（合算） | 要求ミス（1サーバー・入力と生成の合計） |
| --- | ---: | ---: | ---: |
| Phase 1のLRU | 29.24 / 29.22 t/s | 29.23 t/s | 20,183 / 199,680（10.11%） |
| Phase 2の対交換あり | 28.70 / 29.32 t/s | 29.01 t/s | 19,897 / 199,680（9.96%） |

2回目に先立つ交換は48層で各1組、32.3〜34.9 ms。1境界あたりH2D 196,454,400バイト、D2H 98,227,200バイト。生成中の書き戻しは0。終了時のログは2回目の応答後に行った交換も含む。比較の生成速度は交換時間を含まない。実行条件と生ログは Git 外の `/tmp/llama-rocm-phase-2-recovery/`。

H2DとD2Hの初回プレーン転送後に中断する診断を個別に行い、どちらも交換確定0件、RAM原本・保護枠・仮置き枠・所有表が元と一致した。次の応答は通常実行の生成ID・MTP採用数と一致し、その応答後の交換は48件成功した。診断ログは同じディレクトリの `faults/` に保存した。

## Phase 3 利用統計による交換対象の選定

- 比較基準は `7ecd7f5c8` の固定選定。Phase 2のリクエスト境界、転送、300＋20枠、層あたり最大1組を共通とする。
- `LLAMA_EXPERT_HIP_SLOT_EXCHANGE_SELECTION=usage` で、直近のリクエストでルーターに選ばれた回数を比較する。仮置きの利用上位と保護側の利用下位の差が2回以上のときだけ、その1組を交換する。同数の場合は最終利用順を使う。未指定または `fixed` でPhase 2の固定選定を使う。
- 退避を確定したExpertが、次のリクエストで同じRAM枠から仮置き枠に初めて読み込まれた回数を両方式で測る。交換確定数、要求ミス、生成速度、生成IDとMTP採用数も記録する。

### 実機結果

同じビルド・モデル・固定プロンプトで、固定 → 利用統計 → 利用統計 → 固定の順に実行した。各サーバーで入力63・生成128トークンのリクエストをキャッシュ無効で2回送り、全8回答の生成IDが一致した。MTPも各初回で提案73・採用54、各2回目で提案72・採用55が一致した。

| 構成 | 2回目のGeneration（各2回） | 2回目のGeneration（合算） | 要求ミス（1サーバー・入力と生成の合計） | 次のリクエストでの退避後再アップロード |
| --- | ---: | ---: | ---: | ---: |
| Phase 2の固定選定 | 29.50 / 29.49 t/s | 29.50 t/s | 19,897 / 199,680（9.96%） | 23 / 48件、46,720,000バイト |
| Phase 3の利用統計 | 28.96 / 29.67 t/s | 29.31 t/s | 19,753 / 199,680（9.89%） | 0 / 48件、0バイト |

生成中の書き戻しは両条件とも0。交換は各試行の最初の境界で48組。ミス率の差は0.07ポイント、生成速度の差は試行間のばらつきに収まった。同じプロンプトを再送したときの再アップロード数で、2回目の応答後に行った交換は再アップロードの母数から除いた。生ログは Git 外の `/tmp/llama-rocm-phase-3-slot-policy/`。
