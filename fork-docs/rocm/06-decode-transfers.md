# 06 RTX・MI50 の受け渡しと複数位置の転送

基準は `codex/rocm-integrated-test` の `a17eb0c08`。RTX 4070 Ti は通常レイヤーと Router、MI50 は Routed Expert を担当する。

| 作業 | 変更範囲 | 確認条件 |
| --- | --- | --- |
| 06-1a Router ID を再利用 | CUDA から ROCm へ同期コピーする際のホスト側 ID を再利用する。 | 古いスロットの読み取り完了を待ち、2幅 MTP で出力・提案・受理が一致する。 |
| 06-1b GPU 間の受け渡し | 同じ分割内の GPU 間コピーをまとめ、個別の同期と転送の回数を減らす。 | 両方向の転送と実モデルの結果が一致し、カウンタと速度を確認する。 |
| 06-1c GPU 間の単独コピー | 一括化されない戻りの転送で、コピー先の重複した同期を省く。 | MI50からRTXへの発動、出力と MTP 採用数の一致を確認する。 |
| 06-2a 2位置で生成中の並行転送・書き戻し | 1位置で確認した HIP の分割バンクを2位置に広げ、昇格と書き戻しを実行する。 | 下書き1候補で2位置の実行、所有権更新、再読込、GPU 上の重複を確認する。 |
| 06-2b 3位置で生成中の並行転送・書き戻し | 下書き2候補の検証とスクラッチ容量を整え、3位置で同じ処理を実行する。 | 3位置で実際に検証し、拒否時の巻き戻し、所有権、生成結果、重複を確認する。 |

CUDA と HIP 間でランタイム固有のイベントや VRAM ポインタを受け渡さない。GPU 間の同期と MI50 内の転送順序を別に扱い、明示的に有効にした条件で比較する。

## 06-1a Router ID の再利用

`GGML_SCHED_HIP_HOST_ROUTER_IDS=1` で、CUDA から HIP に転送した I32 の Router ID を同一分割の MoE キャッシュで再利用する。再利用できるのは、コピー先を同期し、データのアドレスとバイト数が一致する場合。

Flash Next UD-IQ3_XXS、MTP 下書き1候補、生成32トークンで、OFF/ON の生成トークン列が一致した。両方とも提案18・採用12。読み戻しは960回から0回、74,880バイト減った。速度は23.34から22.16 t/s。短い試行1回で、速度向上は確認できなかった。

## 06-1b GPU 間の入力コピーの一括化

`GGML_SCHED_HIP_BATCH_DEVICE_INPUTS=1` で、CUDA と HIP の標準デバイスバッファ間のコピーを同一分割内でまとめる。両側が参照中のデータを保護するため、各 GPU を自身のランタイムで同期する。同一レイアウトで両側が一括コピーをサポートし、コピー先の範囲が互いに重ならないものを対象にする。

Flash Next、MTP 下書き1候補、生成32トークン、Router ID 再利用ありで、OFF → ON → ON → OFF の4回を実行した。全試行の生成トークン列と MTP 提案18・採用12は一致した。ONの各試行では3,168個のテンソル、49,536,000バイトを1,056組にまとめた。Generation は OFF が25.72 / 24.00 t/s、ON が24.72 / 25.63 t/s。短い試行では差が試行間のばらつきに収まるため、既定はOFFのまま。

4グラフのトレースでは、RTXからMI50への192組を確認した。1組は Router ID、Expert 入力、Router 重みの3テンソル。MI50からRTXへ戻る向きに、一括化の対象は記録されなかった。生ログは Git 外の `/tmp/llama-rocm-06-1b/`。

## 06-1c 単独転送の宛先同期の削減

`GGML_SCHED_HIP_SKIP_DUP_DST_WAIT=1` で、CUDA と HIP の標準デバイスバッファ間の単独コピーで重複していた2回目の宛先同期を省く。スケジューラが単一コピーを使い、複数コピー用イベントがなく、コピー元と先の範囲が有効な場合に限る。最初の宛先同期と転送元同期、ホスト経由のコピーは維持する。`GGML_SCHED_TRACE_EXPERT_HANDOFF=1` の方向別ログで `path=host_skip_dst_wait` を確認できる。

Router ID 再利用と一括コピーを両条件でONにし、生成32トークンを比較した。生成トークン列と提案18・採用12は一致。同期省略は0回から1,056回。4グラフのトレースでは、MI50からRTXへ戻る192件すべてで省略を確認した。RTXからMI50へ送る192件は、両条件とも従来どおり一括化された。生ログは Git 外の `/tmp/llama-rocm-06-1c/`。

## 06-2a 2位置の並行転送と書き戻し

`LLAMA_EXPERT_BATCH_TOKENS=2`、`LLAMA_EXPERT_HIP_OVERLAP=1`、`LLAMA_EXPERT_HIP_OVERLAP_PROMOTION=1` と、`-ub 2 --spec-draft-n-max 1` を使う。両位置の選択を集めてから、最大20枠のコールドバンクに転送する。現在のグラフが読む枠と昇格先が重ならないよう、未使用の常駐枠を使う。後続のコールド演算の前に転送完了を待ち、GPU から読み戻した重みを RAM に書き戻してから所有表を更新する。

比較時は `LLAMA_EXPERT_HIP_OVERLAP=serial` で同じ分割グラフを使う。`LLAMA_EXPERT_HIP_DYNAMIC_RESIDENCY` と `LLAMA_EXPERT_HIP_PREFILL` は外す。`GGML_CUDA_NO_PINNED` も外し、ページ固定の転送領域を使う。

Flash Next、生成128トークン、直列 → 並行 → 並行 → 直列の4回すべてで、トークン列、提案73・採用54、昇格と退避各1,909件、書き戻し3,907,635,200バイトが一致した。詳細ログの直列診断では、退避と同じ Expert・RAM スロットからの後続アップロードを258件確認した。Generation は直列24.01 / 25.42、並行28.35 / 28.30 t/s。同じ分割グラフでの転送タイミングのみを比較した。生ログは Git 外の `/tmp/llama-rocm-06-2a/`。

並行側の別診断で `verify=2 size=2 outputs=2` の生成バッチを73回確認した。`LLAMA_MTP_LOGIT_TRACE=1` を使う場合は、リクエストの上限に加えサーバーにも `-n 128` を指定する。

最終ビルドの32トークン診断を `rocprofv3` で計測した。MI50の転送専用ストリームは2位置の `mul_mat_vec_q_moe` と、H2Dで277.6 ms（転送時間の39.0%）、書き戻しのD2Hで43.9 ms（34.1%）重なった。昇格・退避は各827件で、リクエスト単位のミスも4,957件を記録した。生トレースは Git 外の `/tmp/llama-rocm-06-traces/w2/`。

## 06-2b 3位置の並行転送と書き戻し

MTP 下書き2候補に対応する3位置のグラフを予約し、Qwen4Exp、1シーケンス、ターゲット側の再帰状態スナップショット2つを使う。コールドバンクは30枠へ広げる。通常入力は2位置のまま処理し、下書き2候補を一括検証するときに3枠分の出力と巻き戻しを使う。

HIP の分割バンクには Vulkan 専用の2波スケジューラを適用しない。直列と並行で採用・拒否の結果を照合し、3位置を実際に処理したログと昇格後の再転送を確認する。

2位置の設定に `LLAMA_MTP_VERIFY_THREE=1` を追加し、`--spec-draft-n-max 2` に変更する。`-ub 2` と `--spec-draft-n-ubatch 1` は維持する。Flash Next の直列 → 並行 → 並行 → 直列の4回で、全128トークンと、提案120・採用67が一致した。2候補を提案した60回のうち、先頭を40回、両方を27回採用した。各試行で昇格と退避が各1,992件、書き戻しが4,073,574,400バイト。Generation は直列24.29 / 23.98、並行27.73 / 27.27 t/s。生ログは Git 外の `/tmp/llama-rocm-06-2b/`。

並行側の別診断では `verify=3 size=3 outputs=3` の生成バッチを60回確認した。全候補拒否20回はターゲットとドラフトを2位置、先頭のみ採用13回は両方を1位置巻き戻し、両候補採用27回では巻き戻しは0位置だった。退避先と同じ Expert・RAM スロットからの後続アップロードは288件。

最終ビルドの32トークン診断を `rocprofv3` で計測した。MI50の転送専用ストリームは3位置の `mul_mat_vec_q_moe` と、H2Dで85.2 ms（転送時間の15.1%）、書き戻しのD2Hで67.2 ms（54.5%）重なった。昇格・退避は各740件で、リクエスト単位のミスは4,104件。重複率の分母は、各診断で転送専用ストリームに記録された方向別の転送時間。生トレースは Git 外の `/tmp/llama-rocm-06-traces/w3/`。

2位置と3位置の比較では、同じ入力接頭辞から生成した16トークン目で語句が分かれた。この位置では同じ2候補が上位2つを占め、順位が入れ替わった。候補間の logit 差は2位置で0.17086、3位置で0.00576。3位置の速度を2位置の速度と単純比較する場合は、採用数と生成内容が異なること、および今回の3位置ではドラフトの device-pending 経路が使われないことも考慮する。
