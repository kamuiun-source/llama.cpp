# 04 MI50 内の転送と演算の重複

状態: HIP で必要な機能は確認済み。実装と実機測定は未着手。

## 現状

Vulkan 版は専用の転送処理と遅延 slot map 更新を使う。HIP では同じランタイム内の転送ストリームとイベントを使う候補がある。実機で重複できるかは測定する。

## 小分けの作業

| 作業 | 変更範囲 | 確認してから次に進む条件 |
| --- | --- | --- |
| 04-1 転送バッファを切り替える | [同期の配置と入れ替え](03-expert-placement.md) を基準に、ピン留めステージングからの単独アップロードを実装する。 | 転送内容が同期版と一致し、単独での転送時間が測れる。 |
| 04-2 アップロードと演算を重ねる | 常駐 Expert の演算とスクラッチへの転送を並行化する。 | イベント後にマップを公開し、使用中のスロットを再利用しない。実際の重複を計測する。 |
| 04-3 書き戻しと昇格を重ねる | 退避の書き戻しを加え、完了時にスロットの所有権を更新する。 | ヒット・ミス・退避が重なっても同期版と出力・マップが一致する。 |
| 04-4 広幅 prefill を検証 | Decode の検証後、広幅 prefill のバンク並行転送を独立に追加する。 | 既存の同期経路と同じ結果になり、長い入力で時間差を記録できる。 |

## 完了条件

競合するヒット・ミス・退避を含めて同期版と出力とマップが一致する。同じ入力で GPU 上の重複と全体時間を測り、同期版との差を記録する。
