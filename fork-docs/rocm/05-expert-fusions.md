# 05 Expert カーネル融合と実行回数の削減

状態: 05-1〜05-3 の実機比較を完了。gfx906 の既定は2行・融合有効。対象の融合の有無による実モデルの速度差は、この対話では1%未満だった。

## 現状

共通の CUDA/HIP バックエンドには、gate/up＋SwiGLU の `mul_mat_vec_q_moe` と、Router 重み付きの順次加算をまとめる `moe_weighted_reduction_f32` がある。Vulkan の同等機能を移す判断は、MI50 の既存経路で融合が発動する形状と時間を確認してから行う。

## 05-1 の対象選定

Phase 04-4 の実機トレースを再集計した。MI50 上の2位置・10 Expert の gate/up＋SwiGLU は、IQ3_XXS が各条件42回（中央値154.4 / 154.6 µs）、IQ2_S が52回（158.9 / 159.2 µs）。出力幅2560の Router 重み付き集約は94回（5.76 / 5.92 µs）。いずれも既存の融合カーネル。値は直列 / 並行のトレース内のカーネル時間で、融合の ON/OFF 差ではない。

最初の候補は、時間の長い gate/up＋SwiGLU。Phase 01 と同じ IQ3_XXS、K=2560、M=640、10 Expert 選択で、2位置・3位置それぞれの既存融合と分離実行を照合する。固定3位置の HIP `MUL_MAT_ID` の検証と、Flash-Next 全体の3位置 MTP 検証は区別する。現行の3位置 MTP には Vulkan 限定の経路がある。

### 05-1 の単体計測

IQ3_XXS の合成16 Expertから固定IDで10個を選択し、gate/up＋SwiGLU のみを実行した。MI50、同じバイナリ、各条件100回、OFF → ON → ON → OFF。OFF は `GGML_CUDA_DISABLE_FUSION=1`。値は同期込みの1グラフあたり平均。

| 位置数 | 分離 OFF（µs） | 既存融合 ON（µs） | CPU参照 NMSE |
| --- | --- | --- | --- |
| 2 | 153.370 / 153.060 | 156.690 / 156.600 | 5.65e-5 |
| 3 | 215.680 / 215.780 | 223.270 / 222.670 | 5.55e-5 |

両幅とも ON/OFF の出力は一致した（NMSE 0）。このデータでは融合 ON の方が2位置で約2%、3位置で約3%長かった。合成入力1件の結果なので、モデル全体での既定値の判断には使わない。診断と生ログは Git 外の `/tmp/llama-rocm-05-1/` と `/tmp/llama-rocm-05-1-{off1,on1,on2,off2}.log`。

`rocprofv3` で各幅18グラフ（ウォームアップ8回を含む）を確認した。各グラフの gate/up＋SwiGLU は OFF で5 dispatch（入力量子化2、投影2、SwiGLU 1）、ON で2 dispatch（入力量子化1、融合投影1）。次の実装候補は既存の gfx906 融合カーネルのブロックあたり行数の調整。Vulkan 版の2位置重み共有は既存測定で無効に戻しているため、同じ方式の移植は保留。 [Vulkan の実行フラグ](../teams/runtime-flags.md)

## 05-2 の実装と検証の範囲

gfx906、IQ3_XXS、K=2560、M=640、10 Expert 選択の gate/up＋SwiGLU で、既存カーネルのブロックあたり行数を切り替えて比較する。2位置・3位置の両方で融合を有効にしたまま、同じバイナリと固定入力を使う。CPU 参照、現行出力との差、同期込みの1グラフ時間を照合し、トレースで起動形状を確認する。

`GGML_HIP_GFX906_MOE_SWIGLU_ROWS=1` と `=4` で1行と4行を試す。既定は2行。入力が Expert 間で共有され、通常の SwiGLU を使い、バイアス・追加スケール・Shared Expert の融合を伴わない場合に限定する。出力640行を分割するブロック数は、1行で640、2行で320、4行で160。各行の内積とワープ内加算の順序は同じ。

### 05-2 の実機結果

MI50 で既存融合を有効にしたまま、幅ごとに500回の実行を測った。初回は `2 → 4 → 4 → 2`、最終版では `2 → 1 → 1 → 2` と4行の再確認を行った。以下は最終版の同じバイナリでの1グラフあたり同期込み平均。

| ブロックあたり行数 | 2位置（µs） | 3位置（µs） |
| --- | --- | --- |
| 2（既定） | 154.142 / 153.158 | 226.960 / 226.890 |
| 1 | 153.206 / 153.576 | 228.258 / 228.064 |
| 4（再確認） | 181.846 | 260.188 |

1行・4行とも2行と出力がバイト単位で一致した。CPU 参照との NMSE は2位置で `5.65e-5`、3位置で `5.55e-5`。`rocprofv3` で、各条件が指定した行数の既存融合カーネルを実際に使うことも確認した。

1行の平均差は2位置で約0.2%短く、3位置で約0.5%長かった。4行は再確認で約18%・約15%長かった。既定は2行を維持する。この比較は合成入力での演算単体で、実モデルや MTP の速度は未計測。生ログとトレースは Git 外の `/tmp/llama-rocm-05-2/`。

## 05-3 の実モデル比較

同じ RTX 4070 Ti＋MI50 の Flash-Next UD-IQ3_XXS、同じ配置プロファイルと2行の既定カーネルで比較する。対象は gfx906 の gate/up＋SwiGLU のみ。通常対話と MTP ありを別々に測り、各条件で同じ5つの固定プロンプトを履歴付きで実行する。MTP は RTX 上の Q8_0 下書きに1候補を提案させ、ターゲットの2位置検証を使う。

同じバイナリで各モードの ON/OFF を両順で実行し、生成 ID、回答、prefill と生成時間、MTP の提案数・受理数を保存する。速度計測は通常の CUDA/HIP Graphs 設定を使い、カーネルトレースは別に採る。

OFF は `GGML_HIP_GFX906_DISABLE_ROUTED_SWIGLU_FUSION=1`、ON は未設定。gfx906 の IQ3_XXS・IQ2_S、K=2560、M=640、10 Expert、1・2位置で通常の gate/up＋SwiGLU を使う場合を対象にする。両条件で Router 重み付き集約やグラフの割り当てを揃える。

ターゲットは CUDA0 と ROCm0、通常レイヤーは `--tensor-split 1,0` で CUDA0、Expert はトップ300プロファイルで ROCm0。`--ctx-size 2048 --batch-size 512 --ubatch-size 2 --parallel 1`、`LLAMA_EXPERT_BATCH_TOKENS=2`、HIP 動的常駐とページ固定アップロードを有効化し、広幅 prefill は `LLAMA_EXPERT_HIP_PREFILL=serial`。各セッションの固定5問で履歴と KV を引き継ぎ、温度0、シード1234、生成上限128。MTP 下書きは `draft-mtp`、1候補、下書き ubatch 1、greedy、`--spec-draft-p-min 0`。速度にはモデルのロード時間を含めない。

### 通常対話の結果

ON → OFF → OFF → ON の4セッションすべてで、5回答・640生成トークンの ID とテキストが一致した。初回リクエストの KV キャッシュは空で、各セッションの会話履歴に切り詰めは発生しなかった。生成速度（合計トークン数 ÷ 合計生成時間）は ON が26.12 / 26.21 tok/s、OFF が26.20 / 26.46 tok/s。この入力では差は約0.6%。初回の再試行では同一サーバーへの重複リクエストを確認したため、そのセッションを除外し、空のキャッシュから測り直した。

### MTP ありの結果

同じ順の4セッションすべてで、5回答・640生成トークンの ID とテキストが一致し、会話履歴に切り詰めはなかった。提案・受理は1セッションあたり350件・281件（80.3%）で、ターンごとの件数も一致した。生成速度は ON が31.59 / 31.92 tok/s、OFF が31.91 / 31.41 tok/s。合算値の差は約0.3%で、順序を変えると速い側が入れ替わった。

| ワークロード | 融合 ON の生成速度（tok/s） | 融合 OFF の生成速度（tok/s） |
| --- | --- | --- |
| 通常 | 26.16 | 26.33 |
| MTP あり | 31.75 | 31.66 |

表は各モード・各条件の2セッションを合算した値（総生成トークン ÷ 総生成時間）。この入力では MTP ありの生成が約20〜21%速かった。通常と MTP の間では生成 ID とテキストが一部異なった。生ログと各ターンの出力・計測値は Git 外の `/tmp/llama-rocm-05-3/`。

32トークン上限の実モデル MTP を `rocprofv3` で別に測定した。対象の1位置・2位置の融合カーネルは ON で47回・893回、OFF で0回。OFF では分離したゲート／アップ投影が94回・1,786回に置き換わった。このトレースの Router 重み付き集約は両条件で1,056回。対象融合の切り替えを確認し、通常対話と MTP の結果に基づき既定の融合有効を維持する。生トレースは `/tmp/llama-rocm-05-3/trace-mtp-on` と `trace-mtp-off`。
