# 05 Expert カーネル融合と実行回数の削減

状態: Vulkan 側の対象を特定済み。HIP 実装は未着手。

## 現状

候補は gate/up＋SwiGLU、Router 重み付き集約、グラフ実行の集約。Vulkan のグラフ照合とシェーダーは、HIP の既存カーネルと融合機構に合わせて移す。

## 小分けの作業

| 作業 | 変更範囲 | 確認してから次に進む条件 |
| --- | --- | --- |
| 05-1 計測で対象を選ぶ | [既存 HIP 演算](01-routed-expert.md) と [同期の混在生成](03-expert-placement.md) を基準に、融合候補のコストを個別に見る。 | 最初に実装する融合を1件に絞り、対象形状と時間を記録する。 |
| 05-2 融合1件を実装 | 対象の型・形状・グラフだけを変え、対応外では既存経路を使う。重み付き集約では加算順序を保つ。 | 2位置・3位置で個別に参照と一致し、対象外で既存経路に戻る。 |
| 05-3 ON/OFF を比較 | 同じコードで通常の対話と固定 MTP 条件を両順で測る。 | 生成 ID と MTP 提案・受理、カーネル時間、生成速度を記録し、採否を決める。 |

## 完了条件

融合前後で演算結果が許容範囲内に収まり、代表対話の生成 ID と MTP 提案・受理が一致することを確認する。カーネル時間と生成速度を記録し、実測結果から採否を決める。
