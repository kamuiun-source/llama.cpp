# gfx906のIQ3_XXS gate/up＋SwiGLUのK分割

基準は `codex/rocm-integrated-test` の `d9287e566`。試作は `codex/rocm-gfx906-split-k` で行う。

- 2位置、10ルート、K=2560、M=640、ブロックあたり2出力行を対象とする。Kの量子化10ブロックを5＋5に分け、同一ワークグループでgateとupそれぞれの部分和をLDSで合算してからSwiGLUを適用する。
- 05-2の固定入力を使い、既定版と試作を同じバイナリで切り替えて両順で計測する。出力を既定版とCPU参照に照合し、LDSの合算とSwiGLUを含むカーネル時間および同期込みのグラフ時間を記録する。3位置は対象外の照合に使う。

## 実装と実機結果

`GGML_HIP_GFX906_MOE_SWIGLU_SPLIT_K=1` で試作を選ぶ。64×2×2の起動形状で、後半のgate/up部分和を32バイトの静的LDSに置き、同期後に前半と足してSwiGLUを1回適用する。

| 計測 | 既定 | K分割5＋5 |
| --- | ---: | ---: |
| 2位置の同期込みグラフ時間（500反復、各2回の平均） | 153.84 / 153.73 µs | 168.07 / 168.17 µs |
| 2位置の融合カーネル時間（ウォームアップ後10回の中央値） | 151.20 µs | 166.32 µs |

2位置の12,800要素を照合し、既定版に対するNMSEは `2.14e-14`、絶対誤差の最大値は約 `2.44e-4`。CPU参照へのNMSEは両方とも約 `5.65e-5`。対象外の3位置の19,200要素はバイト単位で一致した。

試作はカーネルで約10.0%、同期込みで約9.3%遅かった。トレースで4waveの起動と融合カーネル1回を確認した。VGPRの報告値は60から64、LDSの報告値は0から512バイト。原因を個別に切り分けるカウンタ測定は未実施。既定の構成を採用し、試作は明示指定で比較できるよう残す。生ログはGit外の `/tmp/llama-rocm-08-split-k/`。
